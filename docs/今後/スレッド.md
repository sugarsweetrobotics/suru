# 今後の候補: スレッド

計画は7段階です。段階1(runtime の下ごしらえ)、段階2(並行開始する・合流する・並行実行する・並列写像する・コア数取得する)、段階3(通路)、段階4(ロック・枠・箱)、段階5(HTTP を接続ごとにスレッドで答える)、段階6(本当の並列: 安全点で止める GC、スレッドごとの確保、箱更新は比較交換)は済みました。

- 段階7 の残り: GC の印付けと片付けを複数のスレッドで行う(今は止めたスレッドの1つが全部行うので、たくさん確保する並列の計算は約 2.2 倍止まり)。関数の入口の安全点は再帰の多い計算で約 15% かかるので、自分を呼ぶだけの再帰は数回に1回だけ見るなどを考える(葉の関数で省くのと、待っている相手だけを起こすのは済みました)
- 複数の通路を同時に待つ(select)、時間切れつきの受信(「ないかもしれない値」の型ができてから)
- 読み書きロック(共有メモリなど外のものを読むスレッドが多いとき。読取実行する・書込実行する)。する の値と箱は読むのにロックが要らないので後回し
