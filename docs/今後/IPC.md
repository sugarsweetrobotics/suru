# 今後の候補: IPC(プロセスどうし)

計画は6段階です(案: https://claude.ai/artifact/WdKdRfxaYSwT5KCojzqqj5 )。段階1(値の直列化、セマフォ内実行する と SEM_UNDO)と段階2(共有箱)、段階3(読み書きロック)、段階4(パイプの通路と子実行する)、段階5(名前つきの通路。案の「共有メモリの輪」ではなく FIFO で作った)、段階6(固定の形と固定領域)は済み、計画は終わりました。

- スレッドどうしの読み書きロック(要るかどうかはスレッドの段階4を作ってから。値は変わらないので箱の読みにはロックが要らない)
- 双方向のパイプの通路(今は1つのプロセスで向きは1つ。行きと帰りで2本作る)
- 名前つきの通路で、送る人が途中から加わっても閉じたと思わない書き方(今は送る側がみな閉じると受け取る側は閉じたと分かる。開き直すか、閉じるのを別に知らせる)
- 共有メモリの輪の通路(FIFO より速い)
- 固定の形に、文字列(決まった長さ)・列挙(赤 か 青 を番号で)・4 バイトや 1 バイトのフィールド(C の int32_t・bool)を足す
- 固定領域のフィールドを1つだけ読み書きする(今は丸ごと。位置は葉のフィールドの番号 × 8)、原子的な加算・比較交換
- 型検査で「してから」の前が型変数のとき、実行してから「動作ではありません」になる(段階6 で lib を書いていて気づいた。純粋な関数の結果を してから で続けても検査で止まらない)
- 復元するときに型を確かめる(今は形の名前とフィールドだけ。型検査の結果をコンパイラから runtime へ渡す必要がある)
- 共有箱に接続するときに中身の型を確かめる(今は復元したときに形の名前とフィールドだけ)
