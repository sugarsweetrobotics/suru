# 成否と有無

計画は issue #86 にあります。

- 段階2: 「した 中身」(Rust の `?`)。成功(有)なら中の値、失敗(無)なら一番内側の関数か手順がその失敗をすぐ返す
- 段階3: `m を 試行する`(「で」を省く)で、実行時エラーを `失敗`(エラーの文)に変える
- 段階3: `試行する` が、手順の2つ目より後の文の中の純粋な計算のエラー(`（x を 数値にする） を 表示する` など)を受け止めずに止まる(インタプリタもコンパイルしたものも)
- 段階4: 失敗の連鎖の表示(自動の経路・`失敗説明する`・`失敗詳細にする`・トップレベルの表示)。`取出する` や `中断する` のエラーの行が、呼んだ行でなく `lib/基本.suru` の行になるのも直す
- 段階5: `JSON結果` を `成否` に置き換え、`数値確認する`(数にできなければ 失敗)を足す
- 構文.suru(点検で使う、する で書いた構文解析)は、基本を自動で読み込むことを知らない(書いた文だけを読む)
