# 成否と有無

計画は issue #86 にあります。

- 「した 中身」の前の値の型が決まらないとき、後から有無と分かっても成否とみなしてエラーになる(型が決まるまで待つ条件にする)
- `試行する` が、純粋な値で始まる手順の続きの中の純粋な計算のエラー(`x とは 「a」 を 結果にした 結果` の後の `（x を 数値にする） を 表示する` など)を受け止めずに止まる。結果にしたものとの連鎖は、手順を作るときにすぐ続きを計算するため(インタプリタもコンパイルしたものも)。行うときまで続きを待つようにする
- `試行する` は標準の関数なので、「で」を省いて使うときも `「標準」 を 読み込む` が要る
- 段階4: 失敗の連鎖の表示(自動の経路・`失敗説明する`・`失敗詳細にする`・トップレベルの表示)。`取出する` や `中断する` のエラーの行が、呼んだ行でなく `lib/基本.suru` の行になるのも直す
- 段階5: `JSON結果` を `成否` に置き換え、`数値確認する`(数にできなければ 失敗)を足す
- 構文.suru(点検で使う、する で書いた構文解析)は、基本を自動で読み込むことを知らない(書いた文だけを読む)
