# 今後の候補: 型の検査

- 同じ型の名前が2通りに出る(#155)。型の引数を書かずに宣言した組(`生徒 とは 名前 と 点 の 組`)は、欄の型を型の引数として推論するので、宣言から出る「（生徒 と 文字列） の 成否」と、推論した「（（（文字列 と 数） の 生徒） と 文字列） の 成否」が混ざる。宣言の型も欄の型を埋めて出すか、欄の型が1通りに決まる組では型の引数を出さないようにする
- `（a と b） の 成功` の「と」はリストなので、型の宣言で組(`（生徒 と 文字列） の 成否`)にしても、違う型の a・b は「リストの要素の型がそろっていません」になる。型の宣言から組として読む
- 関数の定義の引数にも、組のフィールドと同じかっこの型を書く(`n （数） を 階乗する とは …`、#242)。定義の頭の `（` は今は場合ごとの定義のパターンの始まりなので、パターンとぶつからない書き方を別に考える
- 屋台(suru-lang/web)の【API】のまとまりの行(`番号 は 数`)にも、かっこの型(`番号 （数）`)を書けるようにする。suru-lang/web で決める
