# 今後の候補: プロジェクト管理(kumu)

計画は段階に分けています。段階1(雛形・作る・実行)・段階2(依存・組.lock)・段階3(試験・点検)・段階4(公開・VS Code)は済みました。

- 依存の取得を並べて行う、取ってきたものの掃除(kumu 掃除)
- 版の幅(「1.2 以上」など)を書けるようにするか
- 試験を並べて動かす、時間切れ、合格した試験の出力も見る(--詳しく)
- 点検: 「…試験する」の定義には「型の宣言なし」を出さない、依存の中のファイルも見る
- VS Code 拡張に kumu を同梱する(suru-ls と同じく)、試験の結果をテストエクスプローラーに出す
- 版を上げる命令(kumu 版上げ 1.1.0 で 組.suru を書きかえてコミット)
- (後で)中央の登録所
- 外部依存: pkg-config の無い環境(Windows など)での確かめ方、`導入案内` を OS ごとに選んで見せる、`kumu 外部依存` で一覧を出す
- Cソース: `AMENT_PREFIX_PATH` のような `:` 区切りの環境変数から探す書き方、ほかのフォルダのヘッダーの変更も見る、`suru --翻訳`・`suruc` でも使う、マイコン向けでも使う
