# 今後の候補: プロジェクト管理(kumu)

計画は段階に分けています。段階1(雛形・作る・実行)は済みました。

- 段階2 依存: `組.suru` に依存を書き、Git リポジトリから取る(版は Git のタグ)。ロックファイル、`kumu 追加`・`kumu 更新`。読み込みで探す順を「自分のフォルダ → 依存 → 標準の lib」にする(suru・suruc・suru-ls の3つ)。依存の名前が lib の名前と同じならエラー
- 段階3 テストと点検: `kumu 試験`・`kumu 点検` をプロジェクト全体に(テストの書き方は別に決める)
- 段階4 配る: ライブラリを公開する手順、VS Code 拡張から kumu を使う
- 配布(Releases・Homebrew)に suruc と並べて kumu を入れる
- (後で)中央の登録所
