# リリースの手順

「する」は4つの方法で配ります。どれも GitHub Actions がタグから作って公開します。

| 方法 | 入れ方 | 中身 | ワークフロー |
|---|---|---|---|
| PyPI | `pip install suru-lang` | `suru`(Python 版) | `release.yml` |
| GitHub Releases | `suru-版-OS-CPU.tar.gz` を開く | `suruc`・`suru-ls` | `release.yml` |
| Homebrew | `brew install suru-lang/suru/suru` | `suru`・`suruc`・`suru-ls` | `release.yml` |
| VS Code Marketplace | 拡張機能ビューで「する」を検索 | 拡張(`suru-ls` を同梱) | `vscode-release.yml` |

PyPI の名前は `suru-lang` です(`suru` はほかの人が使っています)。入るコマンドは `suru` です。

バイナリを作る(`suru --翻訳`、`suruc`)には、使う人の手元に clang が要ります。Windows 用は `suru-ls` だけです(実行時ライブラリが POSIX 向けなので)。

## 初めに一度だけ用意するもの

公開の前に、次のものを用意します。どれもアカウントの持ち主の手が要ります。

1. **PyPI**: https://pypi.org でアカウントを作り、「Publishing」→「Add a new pending publisher」で次を登録します。トークンは要りません(Trusted Publishing)。
   - PyPI Project Name: `suru-lang`
   - Owner: `suru-lang`、Repository name: `suru`
   - Workflow name: `release.yml`、Environment name: `pypi`
2. **GitHub の environment**: リポジトリの Settings → Environments で `pypi`・`homebrew`・`marketplace` を作ります。「Required reviewers」に自分を入れておくと、公開の前に毎回確認を求められます。
3. **Homebrew の tap**: 空のリポジトリ `suru-lang/homebrew-suru` を作ります。そこに書ける fine-grained token(Contents: Read and write)を作り、environment `homebrew` のシークレット `HOMEBREW_TAP_TOKEN` に入れます。ないときは formula をワークフローのまとめに出すだけです。
4. **VS Code Marketplace**: https://marketplace.visualstudio.com/manage で publisher `suru-lang` を作ります(`editors/vscode/package.json` の `publisher` と同じ名前)。Azure DevOps で Marketplace(Manage)の権限の Personal Access Token を作り、environment `marketplace` のシークレット `VSCE_PAT` に入れます。
5. **Open VSX**(なくてもよい): VSCodium などでも使えるようにするなら、https://open-vsx.org で名前空間 `suru-lang` を作り、トークンをシークレット `OVSX_PAT` に入れます。

## 本体のリリース(PyPI・GitHub Releases・Homebrew)

1. 版を上げます。`suru.py` の `__version__`、`cmd/suruc/main.go` と `cmd/suru-ls/main.go` の `version` を同じ版にします。`python3 packaging/check_version.py v0.1.0` でそろっているか調べられます。
2. main にマージしてから、タグを push します: `git tag v0.1.0 && git push origin v0.1.0`
3. `release.yml` が、テスト → wheel・sdist・バイナリ作り → macOS で動かす → GitHub Releases → PyPI → Homebrew の tap の順に動きます。

公開せずに作るところまで試すには、Actions の画面で「リリース」を手で動かします(Run workflow)。

## VS Code 拡張のリリース

1. `editors/vscode/package.json` の `version` を上げます(本体の版とは別です)。
2. main にマージしてから、タグを push します: `git tag vscode-v0.4.0 && git push origin vscode-v0.4.0`
3. `vscode-release.yml` が、`.vsix` 作り → GitHub Releases → Marketplace(と Open VSX)の順に動きます。

## organization などに移すとき

リポジトリを別の持ち主(GitHub の organization など)に移したら、公開の準備の前に次をします。

1. GitHub でリポジトリを移します(Settings → Transfer ownership)。古い URL からは転送されますが、Go のモジュールの道は転送に頼らず書きかえます。
2. 名前を書きかえます: `python3 packaging/move_owner.py 新しい持ち主 --publisher 新しい publisher`(`--dry-run` で、変わるファイルだけを出せます)。GitHub の URL、Go のモジュールの道(`go.mod` と import)、Homebrew の tap、VS Code 拡張の publisher が変わります。著作権の表示と作者の名前は残ります。`go build ./...` と テストで確かめてから PR にします。
3. 上の「初めに一度だけ用意するもの」を、新しい持ち主で用意します。PyPI の Trusted Publishing の Owner、environment とシークレット(移した先のリポジトリで作り直す)、tap のリポジトリ `新しい持ち主/homebrew-suru`、Marketplace の publisher です。

リリースのワークフロー(`release.yml`・`vscode-release.yml`)は、持ち主とリポジトリの名前を GitHub から受け取るので、書きかえは要りません。PyPI の名前 `suru-lang` も変わりません。

## 手で作るとき

- wheel と sdist: `python3 -m build`(`dist/` にできます)
- バイナリ: `packaging/build_binaries.sh 0.1.0 dist/`
- Homebrew の formula: `python3 packaging/homebrew/make_formula.py 0.1.0 <ソースの tar.gz の sha256>`
- `.vsix`: `cd editors/vscode && npm ci && ./build_server.sh && npx @vscode/vsce package`
