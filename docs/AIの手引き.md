# AI の手引き(「する」を書く・直すときに最初に読むもの)

AI(Claude Code など)が「する」のプログラムを書いたり直したりするときのための、1ファイルの手引きです。文法の要点、よくある間違いと直し方、検査・点検・試験の流し方をまとめています。くわしい決まりは [README_jp.md](../README_jp.md)(英語版は [README.md](../README.md))の「文法のまとめ」と「決めたこと」にあります。

この手引きの ` ```suru ` のコード例は全部、型の検査が通ることを試験で確かめています(`tests/test_ai_guide.py`)。` ```suru-誤り ` の例は、検査でエラーになることを確かめています。

## 直すときの手順

1. **型の検査**: `suru --検査 --json ファイル.suru`(Go 版なら `suruc --検査 --json ファイル.suru`)。構文と型の間違いを、動かす前に見つけます。1回に出るのは最初の1つだけなので、直したらもう一度流します。
2. **点検(linter)**: `suru --点検 --json ファイル.suru …`。エラーではないけれど直すと読みやすくなる書き方を知らせます。
3. **試験**: `suru --試験 ファイルかフォルダ`(名前の一部で選ぶなら `suru --試験 計算.suru 二倍`)。Go 版なら `suruc --試験 ファイルかフォルダ`(ファイルごとにバイナリにして動かす)。kumu のプロジェクトなら `kumu 試験`(`試験/` のフォルダの試験と、ソースのファイルの試験のまとまり・例)。
4. **動かす**: `suru --json ファイル.suru`。実行時のエラーも JSON で出ます。pip で入れた `suru` は、clang があればコンパイルして動かします(README_jp.md の「pip で入れても速く動かす」)。整数の範囲などインタプリタとの違いを疑うときは `suru --インタプリタ --json ファイル.suru` で比べます。

小さな書き方を試すときは、対話モード(`suru`、ファイルを読んでからなら `suru -i ファイル.suru`)が便利です。式を入れるとその値と型を表示します。

### エラーの JSON(`--json`)

`--json` を付けると、エラーと点検の知らせを1行に1つの JSON で出します。出す場所(エラーは標準エラー、点検の知らせは標準出力)と終了コード(問題があれば 1)は付けないときと同じで、問題がなければ何も出しません。

```json
{"file":"a.suru","line":3,"column":7,"kind":"型","rule":null,"message":"「二乗する」の「を」には数が必要ですが、文字列が渡されています"}
{"file":"a.suru","line":5,"column":1,"kind":"点検","rule":"未使用の定義","message":"「y」は定義されていますが、使われていません"}
```

| キー | 中身 |
|---|---|
| `file` | ファイルの道。読み込んだファイルの中のエラーなら、そのファイルの道 |
| `line` ・ `column` | 行と何文字目か(1 から。全角も1文字)。分からなければ `null` |
| `kind` | `構文` ・ `型` ・ `実行` ・ `コンパイル` ・ `点検` |
| `rule` | 点検の規則の名前(点検のときだけ。ほかは `null`) |
| `message` | 日本語の説明。直し方の案内が入っていることが多いので、そのまま従うのが近道です |

使えるところ: `suru --検査`・`suru --点検`・`suru`(実行)・`suru --翻訳`、Go 版の `suruc`(`--検査` も)、`kumu 点検`。

### このリポジトリ(suru 本体)の試験

- Python 版: `python3 -m pytest tests/test_ファイル.py`(変えたところに近いものから)。全部は `python3 -m pytest -n auto tests`(`pip install pytest-xdist` で CPU の数だけ並べて流す)
- CI は PR で変わったファイルを見て、文書だけなら文書の試験だけを流します(`.github/workflows/test.yml`)

## 文法の要点

### 定義と呼び出し

関数名は漢字・カタカナ・英字のあとに「する」で終わります。引数は格助詞(を・に・で・から・へ・より)で区別するので、呼ぶときの語順は自由です。

```suru
数 を 数 で 除算した値にする は 数 を 返す
a を b で 除算した値にする とは a / b です

税率 とは 0.1 です
答えする とは 42 です

（10 を 2 で 除算した値にする） を 表示する
（2 で 10 を 除算した値にする） を 表示する
```

- 1行目は型の宣言です(書かなくても推論しますが、書くとエラーが分かりやすくなります)。終わりの `を 返す` は飾りで、`… は 数` とも書けます。
- 定義の終わりの `です` も飾りで、文として読みやすくするために書きます(書かなくても同じです)。
- 「…して」は前の結果を次の関数の「を」に渡します: `10 を 2 で 除算した値にして 表示する`。
- 呼び出しの結果を算術や引数に使うときは括弧で囲みます(算術は呼び出しより強く結びつきます)。

### リスト

```suru
「標準」 を 読み込んで 使う

数 を 三倍する は 数 を 返す
x を 三倍する とは x * 3 です

並び とは 1 と 2 と 3 です
（並び の それぞれ を 三倍する） を 表示する
（並び から 偶数であること で 選別する） を 表示する
（並び を 0 から （a と b を 受け取って a + b を 返すこと） で 畳み込みする） を 表示する
（並び の 先頭） を 表示する
（1 だけ） を 表示する
```

- 無名関数の `a と b を 受け取って` の a・b は別々の型でよいので、累積値と要素の型が違う畳み込みにも使えます。
- 「と」でリストを作り、`空` が空のリストです。1要素のリストは `1 だけ`(`1 を 空 に 追加する` と同じ。#250)。
- 性質: `の 先頭`・`の 残り`・`の 最後`・`の 長さ`・`の それぞれ`(要素ごとに呼ぶ)。
- 位置は1から数えます: `xs から 1 を 番目取得する` が先頭(`「標準」` が要ります)。

### 条件・場合分け・組

```suru
図形 とは 半径 の 円 か 幅 と 高 の 長方形 です

図形 を 面積にする は 数 を 返す
形 を 面積にする とは
  もし 形 が
    半径 の 円 ならば 3 * 半径 ^ 2 です
    幅 と 高 の 長方形 ならば 幅 * 高 です

数 を 階乗する は 数 を 返す
0 を 階乗する とは 1 です
n を 階乗する とは n * （n - 1 を 階乗する） です

数 が 大きいである は 真偽 を 返す
n が 大きいである とは n > 100 です

（5 の 円） を 面積にして 表示する
（幅 は 2 で 高 は 3 の 長方形） を 面積にして 表示する
5 を 階乗して 表示する
（もし 7 が 大きいである ならば 「大」 そうでなければ 「小」） を 表示する
```

- 「もし … ならば … そうでなければ …」は式で、必ず両方の枝が要ります。
- 「もし 形 が」の後の深い行に、形ごとの場合を並べます(パターンマッチ)。条件は `半径 の 円 かつ 半径 > 10 ならば …`。
- 場合分けの中に場合分けを入れるときは、内側の場合を深く字下げします。外側の場合の字下げに戻ると、内側はそこで終わります。1行に詰めるときは、内側の最後の場合の後に「以上」を書きます: `もしxが1ならば、もしyが1ならば「a」、2ならば「b」以上です、2ならば「c」、そうでなければ「d」。`
- 「…である」で終わる名前は述語(真偽を返す)で、主語を「が」で受けます。否定は「…でない」、値は「…であること」。
- 組のフィールドに型を書けます: `会員 とは 番号 は 数 で 名前 は 文字列 の 組`(`フィールド名 は 型` を `で` で区切る。全部に書くか、どれにも書かないか)。
- 型はフィールド名の後ろのかっこにも書けます: `会員 とは 番号 （数） と 名前 （文字列） の 組`(`と` で区切る。同じ型になります)。1つの型の中では、どちらかの書き方にそろえます。

### 入出力動作と手順

表示や入力は「入出力動作」という値です(型では `数 を 返す 入出力動作`。短く `数 の 動作` とも書けます)。順に行うときは「以下の手順です」から「以上です」までに文を並べます。

```suru
挨拶する は 数 を 返す 入出力動作
挨拶する とは 以下の手順です
  名前 とは 「お名前は? 」 を 入力した 結果
  「こんにちは、」 + 名前 + 「さん」 を 表示する
  名前 の 長さ を 結果にする
  以上です

挨拶してから 表示する
```

- 「以上」は必ず書きます(最後の深い行か、頭と同じ字下げの行)。句読点の書き方では `挨拶するとは、以下の手順です。…。以上です。` です。
- `… とは 手順` + 深い行、1行なら `手順（文。文。）` とも書けます。
- 場合分けの枝にも書けます: `そうでなければ 以下の手順です` + 深い行 + `以上`。`ならば 以下の手順です` + 深い行 + 深い行の `以上` の後には、`もし` と同じ字下げで `そうでなければ …` を続けられます。

- 「…した 結果」は手順の中だけで書けます。関数の本体や「もし」の枝で使うときは、そこを「手順」で囲みます。
- 「…してから」は入出力動作の結果を次に渡します(純粋な値には「して」)。
- 手順の最後の値が全体の結果です。`x を 結果にする` は何もせずに x を結果にする動作です。
- 改行なしで出すのは `続表示する` です。

### 失敗を値で返す(成否と「した 中身」)

```suru
数 と 数 を 安全除算する は （数 と 文字列） の 成否 を 返す
a と b を 安全除算する とは
  もし b = 0 ならば 「0 では割れません」 の 失敗 そうでなければ （a / b） の 成功 です

数 と 数 と 数 を 続けて割算する は （数 と 文字列） の 成否 を 返す
a と b と c を 続けて割算する とは
  x とは a と b を 安全除算した 中身
  （x と c を 安全除算した 中身） の 成功 です

r とは 12 と 3 と 0 を 続けて割算する
（もし r が
  v の 成功 ならば v を 文字列化する
  e の 失敗 ならば 「だめ: 」 + e） を 表示する
```

- `成否`(`値 の 成功 か 理由 の 失敗`)と `有無`(`値 の 有 か 無`)は書けば自動で読み込みます。
- 「…した 中身」は Rust の `?` です。失敗ならその関数がすぐに失敗を返します。
- `r を 取出する` は成功なら中身、失敗なら実行時エラーです。

### ファイルの読み込みと標準ライブラリ

```text
「数学」 を 読み込む                 # 同じフォルダの 数学.suru。中の名前は 数学内の二乗する
「標準」 を 読み込んで 使う          # 前置きなしで 整列する・番目取得する など
「JSON」 を 読み込んで 使う
二乗する と 円周率 は 公開とする    # ファイルの最後に書く(書かなければ全部公開)
```

- 標準のライブラリは `lib/` にあり、どれも する で書いてあります。何があるかは各ファイルの最初の注釈を読むのが早いです(`lib/標準.suru`・`lib/JSON.suru`・`lib/ファイル.suru`・`lib/環境.suru`・`lib/通信.suru` など)。
- 読み込むファイルには定義だけを書きます(`表示する` の文などはエラー)。
- 非標準のライブラリ(HTTP・SQLite・正規表現・GUI)は suru-lang の別のリポジトリにあり、kumu の依存で使います。
- 準クォート `以下は【X】です` … `以上です`(一番外)・`x とは 以下の【X】です` … `以上です` は、読み込んだファイルの `X展開する`(`文字列 を X展開する は 文字列 の 成否`)が返したコードに置きかわります。展開した結果は `suru --展開 ファイル.suru` で見られます。エラーが準クォートの頭の行を指すときは、展開したコードの間違いです。文字列の外の `【】` は頭にだけ書けます。
- 導出 `会員 は 【JSON】 を 導出する` は、`会員` の型の記述(`lib/導出.suru` の `型記述`)を読み込んだファイルの `JSON導出する`(`型記述 を JSON導出する は 文字列 の 成否`)に渡し、返した定義に置きかわります。型は同じファイルで、フィールドの型を書いて定義します。
- JSON との変換は手で書かず `会員 は 【JSON】 を 導出する`(`「JSON」 を 読み込んで 使う`)で作れます: `会員JSON化する` と `会員JSON復元する`(`（会員 と 文字列） の 成否`)。

### 外部の関数(C の関数を呼ぶ)

```suru
外部の「m」 を 読み込む

x を y で 累乗する とは 外部の「pow」 で 小数 を 小数 で 受け取って 小数 を 返します

以下は外部の関数です
  小数 を 余弦にする は 「cos」 で 小数 を 返します
  小数 を 正弦にする は 「sin」 で 小数 を 返します
以上です

以下は外部の入出力動作です
  文字列 を 一行出力する は 「puts」 で 整数 を 返します
以上です

（2 を 10 で 累乗する） を 表示する
「こんにちは」 を 一行出力する
```

- 1つなら `… とは 外部の「C の名前」 で 型 を 受け取って 型 を 返す 入出力動作です` の1行で、たくさんなら `以下は外部の入出力動作です` … `以上です`(動作でないものは `以下は外部の関数です`)に1行に1つずつ書きます。型の宣言と定義の2行で書いてもかまいません。
- まとまりの頭は文の始めなので「以下は外部の…です」と書きます(「以下の外部の…です」も読めますが、新しく書くときは「以下は」にします)。
- 番地で呼ぶ `外部の（f）` も同じに書けます: `p を f で 呼出する とは 外部の（f） で 番地 を 番地 で 受け取って 無 を 返す 入出力動作です`。まとまりの中では名前を付けた形(`… とは （f） で …`)だけで、`は` の短い形には書けません。
- 1行の書き方の型の助詞は、定義の助詞と同じ順に書きます。まとまりの中では、C に渡す引数を並べ替えるときだけ `r を 読取する とは 「f」（r と 0） で 番地 を 受け取って 番地 を 返します` のように名前を付けて書きます。
- 使える型は 数・小数・整数・単精度・真偽・文字列・番地・バイト列・無 です(リストや組は渡せません)。C の構造体は次の「C構造体」で値のまま渡せます。
- C の構造体を値で渡す・返すときは、型を `時間 とは 秒 は 符号付き64 で ナノ秒 は 符号なし32 の C構造体` と宣言して、外部の関数の型に `時間` と書きます。フィールドの型は 符号付き8〜64・符号なし8〜64・単精度・小数・真偽・番地・ほかの C構造体 です。値は `（1 と 2 の 時間）` で作り、`t の 秒` で読みます。
- C構造体を値で渡す関数は、インタプリタと Linux・macOS・Windows のコンパイラで使えます。マイコン向けの小さい する と、主スレッドで呼ぶ外部の関数ではまだ使えません。

### 他の言語から呼ぶ(共有ライブラリ)

する で書いた関数を、Python・C・C++・Go・Rust などから呼べる共有ライブラリにできます(#208)。

```suru
数 を 二倍する は 数 を 返す
x を 二倍する とは x * 2 です

文字列 を 挨拶文にする は 文字列 を 返す
名前 を 挨拶文にする とは 「こんにちは、」 + 名前 + 「さん」 です

以下は外部に出す関数です
  二倍する は 「nibai」
  挨拶文にする は 「aisatsu」
以上です
```

```sh
suruc --共有ライブラリ 計算.suru -o libkeisan.so   # keisan.h も作る(macOS は .dylib、Windows は .dll と .dll.a)
```

- 出す関数には型の宣言が要ります。引数は定義に書いた順に C の引数になります。
- ファイルの一番外には定義だけを書きます(`表示する` などの文があるとエラー)。`以下は外部に出す関数です` がないのもエラーです。
- C の名前は英字・数字・`_` だけで、`rt_`・`suru_`・`gc_` で始まる名前と `main` は使えません。`-o` の名前も英字・数字・`_` だけにします(`libkeisan.so` なら補助の関数は `keisan_free` など)。
- 型の対応: 数 `int64_t`・整数 `int`・小数 `double`・単精度 `float`・真偽 `int`・文字列 `const char *`(値は `malloc` した写しで `keisan_free` で解放)・番地 `void *`・無 `void`。バイト列と数・小数・文字列のリストは番地と長さ、ほかの型は手札 `keisan_value *`(`keisan_release` で放す)。引数に 無 は使えません。
- 実行時エラーで呼んだ側は落ちず、0(NULL)が返って `keisan_last_error()` に文が入ります。
- kumu では 組.suru に `種類 とは 「共有ライブラリ」` と書き、`kumu 作る` で `出力/` に作ります(`kumu 新規 名前 --共有ライブラリ` で雛形)。
- インタプリタと実行ファイルでは、このまとまりを読み飛ばすので、同じファイルを試験や例でそのまま試せます。

### 試験(同じファイルの試験・例・kumu 試験)

実装と同じファイルに、試験のまとまりと例を書けます(#193)。どちらもいつも型を検査し、通常の実行とビルドでは捨て、ファイルを読み込んだときは使いません。`suru --試験 ファイルかフォルダ` で動かします。

```suru
数 を 二倍する は 数 を 返す
x を 二倍する とは x * 2 です
例えば （2 を 二倍する） は 4 です
例えば （-3 を 二倍する） は -6 です

以下は「二倍」の試験です
  （0 を 二倍する） を 0 に 一致確認する
  1 < 2 を 確認する
  以上です
```

- `例えば 式 は 期待する値 です` は、すぐ上の定義の例です。両辺は同じ型の値で、`=` で比べます。
- `以下は「名前」の試験です … 以上です` の中は手順で、「試験」の名前(一致確認する・確認する・不合格にする)を読み込まずに使えます。非公開の名前も使えます。
- どちらも一番外(字下げなし)にだけ書けます。

結合の試験は、`試験/` のフォルダのファイルに、名前が「試験する」で終わる手順として書き、`kumu 試験` で動かします。

```text
「試験」 を 読み込んで 使う
「計算」 を 読み込む

二倍試験する とは 以下の手順です
  （2 を 計算内の二倍する） を 4 に 一致確認する
  1 < 2 を 確認する
  以上です
```

## よくある間違いと直し方

| 間違い | 直し方 |
|---|---|
| ひらがなを含む名前をそのまま書く(`おやつ とは 3`、`割った数にする`) | `『おやつ』 とは 3` のように『』で囲むか、漢字・カタカナにする。**ひらがなだけの関数名は『』でも使えない** |
| 「、」でリストを区切る(`1、2、3`) | 「と」で区切る(`1 と 2 と 3`)。「、」は句読点の書き方の区切り、「・」は予約で文字列の外には書けない |
| 関数名が「する」で終わっていない(`x を 流す とは x`) | `x を 流出する` のように「する」で終わる名前にする |
| 同じ助詞を2回使う(`a を b を 足する`) | 助詞を変えるか、`a と b を` でリストとして受け取る |
| 数と文字列を `+` でつなぐ(`「値: 」 + n`) | `「値: 」 + （n を 文字列化する）` |
| 呼び出しをそのまま算術に使う(`3 を 二乗する + 1`) | `（3 を 二乗する） + 1` |
| 違う型をリストに混ぜる(`1 と 「a」`) | 組か選択肢のある型にまとめる |
| 組の定義で2つの書き方を混ぜる(`番号 （数） と 名前 は 文字列 の 組`) | どちらかにそろえる(`番号 （数） と 名前 （文字列） の 組`) |
| 「…した 結果」を関数の本体や「もし」の枝に書く | そこを `手順` で囲む |
| 動作を純粋な値として使う(`（「?」 を 入力する） + 「!」`) | `「?」 を 入力してから …` か、手順の中で `x とは … を 入力した 結果` |
| 手順の中で `x とは … を 作成する` と「した 結果」を書き忘れ、x を組に入れる(動作そのものが入る) | `x とは … を 作成した 結果`(エラーは「「x」には動作そのものが入っていて、行われていません」) |
| 空白の書き方の行で `a+b` と詰めて書く | `a + b` と空白を入れる(詰めると1つの名前になる)。詰めたいなら、その行を「。」で終わる句読点の書き方にする |
| 文字列に「を1つだけ入れる(`「「」`) | 文字列の中の「」は入れ子として数えるので、`12300 を 文字にする` で作る |
| 改行を文字列に書く | `改行`(「標準」)を `+` でつなぐ |
| 字下げにタブと空白を混ぜる | どちらかにそろえる(半角スペース=1、全角スペース=2、タブ=4 として数える) |
| 読み込んだファイルの名前を前置きなしで使う(`「数学」 を 読み込む` のあとに `二乗する`) | `数学内の二乗する` と書くか、`「数学」 を 読み込んで 使う` にする |
| `… とは 以下の手順です` の後に「以上」を書き忘れる | 手順の最後の文の後に `以上` だけの行を書く(エラーは「「以下の手順です」を閉じる「以上」がありません」) |
| 手順の中で `xs の それぞれ を 表示する` と書く(動作のリストを作るだけで、何も行わない) | `（xs の それぞれ を 表示する） を 実行する` |
| 共有ライブラリにするファイルの一番外に `表示する` などの文を書く | 定義だけにする。試したいことは `例えば … は … です` か試験のまとまりに書く |
| 位置を0から数える | 位置は1から(`xs から 1 を 番目取得する` が先頭) |

検査で確かめられる間違いの例です(上から、ひらがなだけの名前、型の違うリスト、定義のない名前(打ち間違い)、数と文字列の `+`、関数の本体の「した 結果」、「以上」の書き忘れ)。

```suru-誤り
おやつ とは 3
おやつ を 表示する
```

```suru-誤り
1 と 「a」 を 表示する
```

```suru-誤り
数 を 三倍する は 数
x を 三倍する とは x * 3
5 を 三培して 表示する
```

```suru-誤り
数 を 二乗する は 数
x を 二乗する とは x * x
（「値: 」 + （3 を 二乗する）） を 表示する
```

```suru-誤り
数 を 二乗する は 数
x を 二乗する とは x * x
n を 足して表示する とは （n を 二乗した 結果） + 1
```

```suru-誤り
挨拶する とは 以下の手順です
  「こんにちは」 を 表示する
```

## 書き方のそろえ方

- 1つのファイルでは、空白の書き方(`a を 三倍する`)か句読点の書き方(`aを三倍する。`)のどちらかにそろえます(混ぜても動きますが、点検が知らせます)。
- 文末は「する」か「します」にそろえます(点検の「丁寧語の混在」)。
- ライブラリのファイルには、公開する関数の型の宣言を書きます(点検の「型の宣言なし」)。
- 2行以上ある関数の定義と次の関数の定義の間には空行を入れます(点検の「定義の間の空行」)。1行の定義が続くところは空けなくてかまいません。
- 使っていない定義・引数・読み込みは消します(点検の「未使用の…」)。わざと残すときは、その行に `# 点検しない: 規則名` と書きます。

## 読みやすく書く

する は日本語の文として読めることが強みです。かっこが深い式や長い1行は、型の検査は通っても、人にも AI にも読みにくくなります。新しく書くとき・直すときは、次の目安に従います。点検の `長い行`・`かっこが深い`・`無名関数の入れ子` が知らせます(#250)。

- かっこ `（ ）` の入れ子は4重までにします。それより深くなりそうなら、途中の値に名前を付けます。
- 1行は、文字列の中身と注釈を除いて全角で約 100 字までにします。長くなるときは、深く字下げした次の行に続けます。
- 無名関数(`… を 受け取って … を 返すこと`)の中に、もう1つ無名関数を書きません。内側は「ただし」の局所の関数にします。
- 欄の多い組や、長い `… は 非公開とする` の一覧は、字下げして1行に1つ(か、まとまりごと)に書きます。

### 深く字下げした行は前の行の続き

「…して」の連鎖や長い一覧は、深く字下げした行に分けられます。分ける前は、置換が8つ1行に並んでいました。

```suru
「標準」 を 読み込んで 使う

文字列 を 日付書式にする は 文字列
型 を 日付書式にする とは
  型 を 「%Y」 から 「2026」 へ 置換して
    「%m」 から 「11」 へ 置換して
    「%d」 から 「28」 へ 置換する

「%Y-%m-%d」 を 日付書式にして 表示する
```

組の欄も1行に1つ書けます。欄の横に注釈を書けるので、欄の意味を上にまとめて書くより読みやすくなります。

```suru
設定 とは
  宛先群 は 文字列 の リスト で
  静か は 真偽 で          # -s
  方法 は 文字列 の 組     # -X

既定設定 とは 宛先群 は 空 で 静か は 偽 で 方法 は 「GET」 の 設定
（既定設定 の 方法） を 表示する
```

### 途中の値に名前を付ける

かっこが深いときは、「ただし」(手順の中なら `x とは …`)で部分に名前を付けます。名前が、その部分が何かの説明になります。

```
# 読みにくい: 何の条件かは、5重のかっこを最後まで読まないと分からない
（（（「名前」 と 「花%」 の 類似条件） と （「名前」 の 無値条件）） の 一部条件） …
```

```suru
数 の リスト を 平均との差にする は 数 の リスト
xs を 平均との差にする とは xs の それぞれ を 差にする
ただし 平均 とは 合計 / （xs の 長さ）
ただし 合計 とは xs を 0 から （a と b を 受け取って a + b を 返すこと） で 畳み込みする
ただし x を 差にする とは x - 平均

（1 と 2 と 6） を 平均との差にして 表示する
```

### 無名関数の入れ子は「ただし」の関数に

「ただし」に書いた局所の関数は、外の関数の引数を使えます。無名関数の中に無名関数を書く代わりに、内側に名前を付けます。

```
# 読みにくい: 受け取って … を 返すこと が2重で、かっこが6重
xs を k で 倍数拾うする とは （（1 と 2） を （n を 受け取って （xs から （x を 受け取って x = n * k を 返すこと） で 選別する） を 返すこと） で 写像する） を 連結する
```

```suru
「標準」 を 読み込んで 使う

数 の リスト を 数 で 倍数拾うする は 数 の リスト
xs を k で 倍数拾うする とは （（1 と 2） を 倍拾うすること で 写像する） を 連結する
ただし n を 倍拾うする とは xs から （x を 受け取って x = n * k を 返すこと） で 選別する

（2 と 4 と 3） を 2 で 倍数拾うして 表示する
```

## 名前の付け方

名前は、中を読まなくても何をするかが分かるように付けます。

- 関数は「名詞+動詞する」にします(`品一覧する`・`行数数える` より `行数にする`)。変換は「…にする」、真偽を返すものは「…である」、値は名詞にします。
- 名前の中に「して」を入れません。「して」は呼び出しをつなぐ言葉なので、`足して二倍する` は2つの呼び出しに見えます。2つのことをするなら2つの関数にして、`x を 足して 二倍する` とつなぎます(点検の `して入りの名前`、#250)。
- 一番外の名前や公開する名前は、略しすぎません。`器引助`・`資印` のような漢字1〜2字の組み合わせは、定義を読まないと分かりません。関数の中の局所の名前は短くてもかまいません。
- ひらがなを含む名前は『』で囲みます(ひらがなだけの名前は使えません)。

```
# 読みにくい: 「一足して」「二倍する」の2つの呼び出しに見える
x を 一足して二倍する とは （x + 1） * 2
```

```suru
数 を 一足する は 数
x を 一足する とは x + 1

数 を 二倍する は 数
x を 二倍する とは x * 2

3 を 一足して 二倍して 表示する
```
