# する のライブラリを公開する

する のライブラリは、Git のリポジトリにタグを付けるだけで、ほかの人が `kumu 追加` で使えるようになります。中央の登録所はありません。

## 1. ライブラリを作る

```sh
kumu 新規 計算
cd 計算
```

`組.suru` の `名前` が、使う人が読み込むときの名前になります。読み込まれるのは、名前と同じファイル `計算.suru` です(雛形の `本体.suru` は、ライブラリなら消してかまいません)。

```
# 計算.suru
x を 二倍する とは x * 2
x を 三倍する とは x * 3
```

中のほかのファイルは `「計算/道具」` のように読み込めます(`道具.suru`)。使う人に見せたくない定義は、ファイルの終わりに `補助 は 非公開とする` のように書きます(README の「公開と非公開」)。

## 2. 試験を書く

`試験/` のフォルダに、名前が「試験する」で終わる手順を書きます。ライブラリ自身は、使う人と同じく `「計算」` で読み込めます。

```
# 試験/二倍.suru
「試験」 を 読み込んで 使う
「計算」 を 読み込む

二倍試験する とは 手順
  （2 を 計算内の二倍する） を 4 に 一致確認する
  （0 を 計算内の二倍する） を 0 に 一致確認する
```

```sh
kumu 試験
kumu 点検
```

## 3. 版を決めてタグを付ける

`組.suru` の `版` を `「1.0.0」` のように数と点で書き、コミットしてから `kumu 公開` を実行します。

```sh
git add -A && git commit -m "1.0.0"
kumu 公開
git push origin v1.0.0
```

`kumu 公開` は、次のことを確かめてから、`v1.0.0` の注釈つきタグを付けます(push はしません)。

- `名前.suru` があること
- 依存に手元のフォルダ(`「../…」`)がないこと(使う人は取ってこられないため)
- 組.suru がリポジトリの一番上にあり、コミットしていない変更がないこと
- 同じ版のタグがまだないこと
- 試験が全部合格すること(`--試験なし` で飛ばせます)

## 4. 使ってもらう

```sh
kumu 追加 github.com/someone/計算        # 一番新しいタグ
kumu 追加 github.com/someone/計算@1.0.0  # 版を決める
```

```
「計算」 を 読み込む
3 を 計算内の二倍して 表示する
```

## 版の上げ方

一度 push したタグは動かさないでください。使う人の `組.lock` にはコミットと中身のハッシュが書いてあるので、タグを動かすと、使う人の kumu が「コミットが 組.lock と違います」のエラーで止まります。直したいときは、版を上げて新しいタグを付けます。

- 使い方が変わらない直し: `1.0.0` → `1.0.1`
- 関数を足した: `1.0.0` → `1.1.0`
- 関数の名前や引数を変えた: `1.0.0` → `2.0.0`

同じライブラリを違う版で求められたときは、一番新しい版が使われます(kumu 段階2 の決まり)。古い版の使い方で書いたライブラリと一緒に使われることがあるので、使い方を変えるときは大きい数(一番左)を上げます。
