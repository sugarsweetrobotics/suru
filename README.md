# 日本語関数型プログラミング言語「する」(プロトタイプ)

Python 3.10 以降だけで動くインタプリタです(外部ライブラリ不要。テストに pytest を使います)。

```sh
python3 suru.py examples/basic.suru   # 型を調べてから実行(トップレベルの式の値を1行ずつ表示)
python3 suru.py --検査 examples/basic.suru  # 実行せずに型の間違いを探す(--check も可)
python3 suru.py --検査なし examples/basic.suru  # 型を調べずに実行(--no-check も可)
python3 suru.py                       # 対話モード
python3 suru.py --翻訳 examples/basic.suru  # バイナリ examples/basic を作る(--compile も可。clang が必要)
python3 -m pytest tests               # テスト
```

### pip で入れる

```sh
pip install git+https://github.com/sugarsweetrobotics/suru   # または、取ってきたフォルダで pip install .
suru examples/basic.suru          # python3 suru.py と同じ(--検査・--検査なし・--翻訳 も使えます)
suru --version
```

標準ライブラリ(`lib/標準.suru`)とコンパイラの実行時ライブラリ(`runtime/suru_rt.c`)も一緒に入ります。`--翻訳` には clang が別に必要です。

### 速いコンパイラ(Go 版)

`--翻訳` と同じことを、Go で書いたコンパイラ `suruc` でもできます。出す LLVM IR は Python 版と一字一句同じで、IR を作るまでが 14〜35 倍ほど速くなります(Go 1.23 以降が必要です)。

```sh
go install github.com/sugarsweetrobotics/suru/cmd/suruc@latest   # または、取ってきたフォルダで go build ./cmd/suruc
suruc examples/basic.suru          # バイナリ examples/basic を作る(clang が必要)
suruc -O0 examples/basic.suru      # clang の最適化を弱めて、もっと速く作る(-O0 〜 -O3。既定は -O2)
suruc --ll examples/basic.suru     # LLVM IR だけを出す
```

`suruc` は1つの実行ファイルで、標準ライブラリと実行時ライブラリを中に持っています(`SURU_LIB` で lib/ の場所を変えられます)。

### VS Code 拡張

`editors/vscode/` に VS Code 拡張があります。色分け(関数名・格助詞・キーワード・文字列・『』の名前など。空白の書き方と句読点の書き方の両方)、書きながらの型の検査(間違いに波線)、型のホバー、定義へ移動、定義の一覧、▷ か F5 での実行、バイナリ作りができます。書きながらの検査・ホバー・定義へ移動は、Go 版の検査を使う言語サーバー `suru-ls`(`cmd/suru-ls`)が行います。入れ方は [editors/vscode/README.md](editors/vscode/README.md) にあります。

## 例

```
a　と　b　を加算する　とは　a + b

引数　を三倍する　とは　引数　と　引数　を加算して　引数　を加算する

1　と　2　を加算する      # → 3
5　を三倍する             # → 15
```

```
a を b で 割る数にする とは a / b
2 で 10 を 割る数にする              # → 5(助詞で引数が決まるので語順は自由)

リスト とは 1 と 2 と 3
リスト の それぞれ を 三倍する        # → （3 と 6 と 9）
リスト から 偶数判定すること で 選別する
5 に （1 を 加算すること） を 適用する  # → 6
```

空白や改行を使わず、句読点で詰めて書くこともできます(両方の書き方を同じファイルで混ぜてもかまいません)。

```
aとbを加算するとは、a+b。引数を三倍するとは、引数と引数を加算して、引数を加算する。
1と2を加算する。5を三倍する。                         # → 3、15
aとbを平均するとは、合計/2。ただし、合計とは、a+b。   # 局所定義は「ただし」で
```

組(名前付きタプル)、選択肢のある型、パターンマッチ、性質(型クラス)も使えます。

```
図形 とは 半径 の 円 か 幅 と 高 の 長方形

形 を 面積にする とは
  もし 形 が
    半径 の 円 ならば 3 * 半径 ^ 2
    幅 と 高 の 長方形 ならば 幅 * 高

5 の 円 を 面積にする                        # → 75
幅 は 2 で 高 は 3 の 長方形 を 面積にする    # → 6
```

引数に値や形を書くと、場合ごとに関数を定義できます。パターンには「かつ」で条件を付けられます。

```
0 を 階乗する とは 1
n を 階乗する とは n * （n - 1 を 階乗する）

空 を 合計する とは 0
先頭 は x で 残り は 他 を 合計する とは x + （他 を 合計する）

形 を 分類する とは
  もし 形 が
    半径 の 円 かつ 半径 >= 10 ならば 「大きい円」
    半径 の 円 ならば 「円」
    そうでなければ 「長方形」
```

「…である」で終わる名前は述語(真か偽を返す関数)で、主語を「が」で受けます。

```
n が 偶数である とは n % 2 が 0
もし n が 偶数である ならば 「偶」 そうでなければ 「奇」
3 が 偶数でない                                # → 真
リスト から 偶数であること で 選別する
```

画面への出力や入力のような副作用は「動作」という値で扱い、「手順」で順に行います。

```
挨拶するとは、手順（
  名前とは、「お名前は? 」を入力した結果。     # 「…した 結果」で動作の結果を受け取る
  「こんにちは、」+名前+「さん」を表示する。
  名前の長さを結果にする）。
挨拶してから、表示する。                       # 「してから」は前の動作の結果を「を」に渡す
「はじめ」を表示する。それから、「おわり」を表示する。
```

`examples/stdlib.suru` と `examples/stdlib_open.suru` には標準ライブラリの例、`examples/predicate.suru` には述語の例、`examples/cases.suru` には場合ごとの関数定義とパターンの条件の例、`examples/io.suru` には動作と手順の例、`examples/fib_input.suru` には個数を尋ねてフィボナッチ数列を表示する例、`examples/data.suru` には組・パターンマッチ・性質の例、`examples/punct.suru` には句読点の書き方の例、`examples/more.suru` には改行・インデント、局所定義、条件分岐と再帰、長いパイプラインの例、`examples/list.suru` には助詞の引数、リスト、高階関数の例があります。

## 文法のまとめ

| 書き方 | 意味 |
|---|---|
| `a を b で 除算する とは a / b` | 関数の定義。引数名の後に**格助詞**(を・に・で・から・へ・より)を付ける。関数名は「する」で終わる |
| `10 を 2 で 除算する` / `2 で 10 を 除算する` | 呼び出し。引数は助詞で対応するので語順は自由 |
| `答えする とは 42` | 引数なしの関数 |
| `税率 とは 0.1` | 値の定義(名前が「する」で終わらないもの) |
| `10 を 2 で 除算して 3 に 加算する` | パイプライン。「…して」の結果が次の関数の**「を」**に入る |
| `1 と 2 と 3`、`空` | リスト、空リスト |
| `a と b を 加算する とは a + b` | 「を」にリストを受け取り、分解して a・b に入れる |
| `リスト の 先頭` `の 残り` `の 最後` `の 長さ` | リストの性質 |
| `x を リスト に 追加する` / `挿入する` | 末尾 / 先頭に足した新しいリスト |
| `もし リスト が 空 ならば …` | 「が」は等しいかどうか(`==` と同じ) |
| `n が 偶数である とは …` | 述語(真偽を返す関数)の定義。主語は「が」 |
| `4 が 偶数である` / `3 が 偶数でない` / `偶数であること` | 述語の呼び出し / 否定 / 述語そのもの(値) |
| `三倍すること`、`1 を 加算すること` | 関数そのもの(値)。引数が足りなければ部分適用 |
| `x を 受け取って x * 2 を 返すこと` | 無名関数 |
| `リスト の それぞれ を 三倍する` | 要素ごとに呼び出して、結果のリストを返す(map) |
| `もし 条件 ならば 式 そうでなければ 式` | 条件分岐(式なので必ず値を返す) |
| `+ - * / % ^`、`× ÷`、全角の `＋－＊／` | 算術(`^` はべき乗)。リストどうしの `+` は連結 |
| `== != < > <= >=`、`= ≠ ≦ ≧` | 比較。結果は `真` / `偽` |
| `条件 かつ 条件`、`条件 または 条件` | 真偽の「かつ」「または」(左で決まれば右は計算しない) |
| `( … )` `（ … ）` | 括弧。呼び出しを算術式や引数に埋め込むときにも使う |
| `「文字列」` | 文字列。`+` で連結 |
| `#`・`＃`・`※` | 行末までコメント |
| `5を三倍する。` | 句読点の書き方。「。」で文が終わり、「、」は区切り。空白なしで詰めて書ける |
| `5を三倍します。`、`5を三倍しまして、表示します。`、`p とは 3 と 4 の 点 です。` | 丁寧語の文末。「します」は「する」、「しまして」は「して」と同じ。文末の「です」は読み捨てる |
| `… とは、本体。ただし、合計とは、a+b。` | 「ただし」で直前の定義に局所定義を付け足す |
| `（合計とは、a+b。合計/2）` | 括弧の中に「。」で文を並べたブロック(最後の文が値) |
| `『おやつの数』` | ひらがなを含む名前(『』で囲む) |
| `点 とは 横 と 縦 の 組` | 組(名前付きタプル)の型の定義 |
| `図形 とは 半径 の 円 か 幅 と 高 の 長方形`、`信号 とは 赤 か 黄 か 青` | 選択肢のある型(「か」で形を並べる) |
| `3 と 4 の 点` / `横 は 3 で 縦 は 4 の 点` | 組を作る(順番どおり / 名前つき) |
| `p の 横`、`横 は 10 の p` | フィールドを取り出す、1つだけ変えた新しい組を作る |
| `もし 形 が` + 深い行に `半径 の 円 ならば …` | パターンマッチ(場合分け) |
| `先頭 は x で 残り は 他 ならば …` | 空でないリストを先頭と残りに分解する |
| `半径 の 円 かつ 半径 > 10 ならば …` | パターンの条件(ガード) |
| `0 を 階乗する とは 1` + `n を 階乗する とは …` | 場合ごとの関数定義(引数にパターンを書く。上から順に使う) |
| `比較可能 という 性質 とは …` / `点 は 比較可能` | 性質(型クラス)の定義と実装 |
| `x を 表示する`、`入力する` | 動作(副作用)を作る。トップレベルに書くと行われる |
| `手順（文。文。…）` / `… とは 手順` + 深い行 | 文を順に行う(do 記法)。最後の文が全体の動作 |
| `名前 とは 入力した 結果` | 手順の中で動作を行い、その結果に名前を付ける(バインド) |
| `入力してから 表示する` | 前の動作の結果を次の関数の「を」に渡す(バインド) |
| `（入力する） の 結果 を 数値にする` | 動作の結果に関数を適用する(写像) |
| `x を 結果にする` | 何もせずに x を結果とする動作(pure / return) |
| `…。それから、…。` | 前の文の後に続けて行う |

### 組み込み関数

| 呼び出し | 意味 |
|---|---|
| `x を 表示する` | x を表示する動作(結果は x) |
| `入力する`、`「質問」 を 入力する` | 1行読む動作(結果は文字列)。「を」があれば先に表示する |
| `「12」 を 数値にする` | 文字列を数にする(全角も可。数にできなければエラー) |
| `動作のリスト を 実行する` | 動作を順に行う動作(結果は結果のリスト) |
| `x を 結果にする` | 何もせずに x を結果とする動作 |
| `m を f で 連鎖する` | m を行い、結果を f に渡す(性質「連鎖可能」の関数。リストなら f の結果をつなげる) |
| `x を 絶対値にする` | 絶対値 |
| `xs を 加算する`、`x を y に 加算する` | 合計(「を」がリストなら全部足す。「に」は省略可) |
| `xs を 乗算する`、`x を y に 乗算する` | 積 |
| `a から b を 減算する` | a - b |
| `a を b で 除算する` | a / b |
| `x を リスト に 追加する` / `挿入する` | 末尾 / 先頭に足したリスト |
| `関数 を x に 適用する` | 関数を x に適用(「に」を省くと引数なしで呼ぶ) |
| `リスト から 関数 で 選別する` | 関数が 真 を返す要素だけのリスト(filter) |
| `リスト を 関数 で 写像する` | 各要素に関数を適用したリスト(map)。性質「写像可能」の関数で、動作にも使える |
| `リスト を 初期値 から 関数 で 畳み込みする` | 左からの畳み込み(fold) |

組み込みと同じ名前の関数を定義すると、定義したほうが使われます。

## 決めたこと(仕様で曖昧だった点)

1. **引数は格助詞で区別する。** 使える助詞は「を・に・で・から・へ・より」。1つの関数で同じ助詞は1回までです(定義でも呼び出しでも、2回目はエラー)。足りない引数や、受け取らない助詞を渡すとエラーです。
2. **助詞は関数名にくっついていてよい。** `を加算する` と `を 加算する` は同じです。`で除算する`、`を返すこと` なども同様です。**ひらがなだけの関数名は使えません**(`へんかんする` はエラー。「する」の前に漢字かカタカナが必要です)。
3. **「…して」は関数合成(パイプライン)。** 前の結果は次の関数の「を」に入ります。次の区間に「を」の引数も書いてあるときは、**前の結果を先頭に並べたリスト**になります。`引数 と 引数 を加算して 引数 を加算する` は `加算(を = (加算(を = (引数, 引数)) と 引数))` です。式は必ず「…する」で終わります(「…して」で終わるとエラー)。
4. **「と」はリストを作る。** `1 と 2 と 3` は3要素のリストです。算術と比較は「と」より強く結びつくので、`1 + 1 と 2 * 3` は `（2 と 6）` です。1要素のリストは `1 を 空 に 追加する` で作ります。リストは変更できない値で、`（1 と 2 と 3）` のように表示します。
5. **定義の「a と b を」はリストの分解。** 渡されたリストの長さが合わないとエラーです。これで最初の例 `a と b を加算する とは a + b` は今まで通り動きます。
6. **読点「、」は句読点の書き方の区切り、中黒「・」は予約。** 「、」はリストの区切りには使いません(20 以降を参照)。「・」は文字列の外に書くとエラーです。
7. **「の」の後はリストの性質かフィールド名。** 先頭・残り・最後・長さ・それぞれ はリストの性質、それ以外の名前は組のフィールドです(`p の 横`)。算術より強く結びつきます(`リスト の 先頭 + 1` は `(リスト の 先頭) + 1`)。「の」の後が型の形の名前のときだけは組を作る意味になり、結びつきが変わります(28番)。
8. **「が」は等しいかどうか。** `リスト が 空` は `リスト == 空` と同じです。「もし」の直後の「が」はパターンマッチになりますが、パターンが値だけなら意味は同じです(31番)。
9. **「〜すること」は関数の値。** 区間の最後にある「こと」は、前に並んだ引数を受け取って部分適用になります(`1 を 加算すること`)。後ろに助詞が続く「こと」は、それ自体が外側の呼び出しの引数になり、前の引数は外側のものです(`リスト を 0 から 加算すること で 畳み込みする` の `0 から` は 畳み込み の引数)。部分適用した関数を外側の引数に渡すときは括弧で囲みます: `5 に （1 を 加算すること） を 適用する`。
10. **関数の値に値を渡すときは、まだ渡していない引数を定義の順に埋める。** 組み込みは表の順(加算する なら を → に)です。必須の引数が残れば、さらに部分適用になります。畳み込みでは、必須の引数が2つ以上ある関数には「累積値」「要素」を別々に、1つの関数には `（累積値 と 要素）` のリストとして渡します。
11. **「それぞれ」は1回の呼び出しにだけかかる。** `リスト の それぞれ を 三倍する` は三倍した結果のリストを返します。同じ呼び出しに「それぞれ」が2つあると、同じ位置の要素どうしで呼び出します(長さが違うとエラー)。呼び出しの引数以外に書いた `リスト の それぞれ` はリストそのものです。
12. **無名関数** `x を 受け取って 本体 を 返すこと`。引数の書き方は定義と同じです(`a と b を 受け取って` も可)。外側の変数を覚えます(クロージャ)。他の引数より前に書くときは括弧で囲みます。
13. **名前の予約。** 「する」「して」「すること」で終わる単語は常に関数とみなすので、変数名には使えません。`と` `とは` `の` `が` `を` `に` `で` `から` `へ` `より` `もし` `ならば` `そうでなければ` `受け取って` `返すこと` `ただし` `か` `は` `という` `組` `性質` `それから` `かつ` `または` `読み込む` `読み込んで` `使う` `真` `偽` `空` も予約語です。「…した」で終わる単語(`入力した`)と「…してから」で終わる単語も関数の呼び出しです。「…である」「…でない」「…であること」で終わる単語は述語の呼び出しです(47番)。`結果` と `手順` は予約語ではなく、決まった位置(36番以降)でだけ特別な意味になります。
14. **算術は呼び出しより強く結びつく。** 呼び出しの結果を計算に使うときは `( 1 と 2 を加算する ) * 3` と括弧で囲みます。
15. **空白の書き方ではトークンはスペース区切り。** `a+b` のように詰めて書くと1つの名前になります。例外として括弧と「」『』は詰めて書いても区切ります。詰めて書きたいときは句読点の書き方(20)を使ってください。
16. **オフサイドルール。** 行頭のインデント幅で構造を決めます(半角スペース=1、全角スペース=2、タブ=4)。
   - 「とは」で行が終わると、次の深い行たちが本体ブロックになります。ブロックの中には局所定義を並べられ、**最後の行の式が値**になります。
   - 「とは」の後に同じ行で本体を書いた場合や、普通の式の行の後に深い行が続く場合、深い行は式の**続き**です。
   - 同じ深さの行が `ならば` / `そうでなければ` で始まるときは、前の行の続きとみなします(条件分岐を縦に並べて書けるように)。
   - 深さが前のどのブロックとも合わない行はエラーです。
17. **定義の順番は自由。** トップレベルの定義は先にすべて登録されるので、使う場所より後ろで定義しても、相互再帰でも動きます。
18. **割り算。** 整数どうしで割り切れるときは整数、そうでなければ小数になります。0 で割るとエラーです。
19. **エラーは日本語で、行番号と何文字目か付き。** `2行目 6文字目: 「存在しない数にする」は定義されていません` のように出し、ファイルを実行したときや対話モードでは、その行と位置の印(`^`)も表示します。全角の文字は2文字分の幅で印の位置を合わせます。実行時のエラーは、その式の始まり(算術ならその演算子)の位置を指します。

### 句読点の書き方

20. **「。」か「、」を含む行は句読点の書き方。** その行から始まる文は「。」で終わります。「。」までは改行をまたいでよく(字下げも自由)、1行に何文書いてもかまいません。「。」で終わらないまま最後まで来るとエラーです。「、」は空白と同じ区切りで、どこに書いてもよく、パターンマッチの場合の区切り(31番)のほかは意味を持ちません(`とは、` や `して、` の後に置くと読みやすい)。文字列の中の「。」「、」は関係ありません。「。」や「、」のない行は今まで通り空白とインデントの書き方なので、両方を1つのファイルに混ぜられます。
21. **単語は文字の種類の境目で切る。** 漢字・カタカナ・英字の並びは名前(英字の後の数字は名前の続き: `x1`)、数字の並びは数、記号の並びは演算子です。ひらがなの並びは 助詞(を・に・で・から・へ・より)、キーワード(と・とは・の・が・もし・ならば・そうでなければ・それぞれ・ただし・か・は・という)、「する/して/すること」に分けます。`長さ` `残り` `受け取って` `返すこと` と組み込みの `畳み込み` はひらがなを含みますが、決まった言葉として読みます。
22. **関数名は「する」の直前の名前から。** `リストを三倍する` は `リスト を 三倍する` です。「する」と同じひらがなの並びにある前の部分は関数名に入ります(`三倍にする` `絶対値にする`)。
23. **名前は漢字・カタカナ・英字で書く。** 送り仮名などのひらがなは助詞と区別できないので、ひらがなを含む名前は 『おやつの数』 のように『』で囲みます(「」は文字列なので『』にしました)。ひらがなの混ざった関数名は 『割る数に』する のように書けます(空白の書き方の `割る数にする` と同じ関数です)。
24. **ひらがなだけの名前はエラー。** どちらの書き方でも、ひらがなだけの名前(`するめいか とは 3`、`あ を 受け取って …`)を定義しようとすると、漢字かカタカナを使うか『』で囲むよう案内するエラーになります。『』で囲めばひらがなだけの変数名も使えますが、**ひらがなだけの関数名は『』で囲んでも使えません**。
25. **局所定義は「ただし」で付け足す。** `aとbを平均するとは、合計/2。ただし、合計とは、a+b。` の「ただし」の文は、直前の(ただしでない)定義の中の局所定義になります。続けて何個でも書けます。空白の書き方でも `ただし 合計 とは a + b` の行として使えます。定義でない文の後に「ただし」を書くとエラーです。
26. **括弧の中に文を並べられる。** 括弧の中に「。」か「とは」があれば、「。」で区切った文の並び(ブロック)として読み、最後の文の値が括弧の値になります: `（積とは、a*b。積^0.5）`。局所定義の中にさらに局所定義を書くときや、式の途中で名前を付けたいときに使います。
27. **「もし」は閉じなくてよい。** 「もし … ならば … そうでなければ …」は必ず両方の枝があるので、入れ子にしても区切りが一意に決まります。「そうでなければ」の後は文の終わり(か閉じ括弧)まで続くので、途中で終わらせたいときは括弧で囲みます。パターンマッチの場合分け(31番)は、形が全部そろっていれば「そうでなければ」を省けます。

### 組・パターンマッチ・性質

28. **組の型は「… の 組」、選択肢のある型は「か」で定義する。** `点 とは 横 と 縦 の 組` は、横・縦を持つ型「点」です(形の名前も「点」)。`図形 とは 半径 の 円 か 幅 と 高 の 長方形` は、円か長方形のどちらかの形をとる型です。中身のない形だけを並べると列挙型になります(`信号 とは 赤 か 黄 か 青`、`赤` はそのまま値)。型の定義は一番外側に書き、どこで使うより後ろに書いてもかまいません。型名・形の名前・フィールド名は変数名と同じ決まり(ひらがなを含むなら『』)で、形の名前はプログラム全体で1つの型にしか使えません。フィールド名を型や形の名前と同じにするとエラーです。
29. **組を作る。** 順番どおりなら `3 と 4 の 点`、名前つきなら `横 は 3 で 縦 は 4 の 点`(順番は自由。全部のフィールドが必要)です。**「… の 形の名前」は、「と」で並べた左側の値の全体にかかります**(`3 と 4 の 点` は `（3 と 4） の 点`)。そのため、組を「と」で並べるときは `（1 と 2 の 点） と （3 と 4 の 点）` と括弧で囲みます(囲まないとエラーで案内します)。`（3 と 4） の 点` のようにリストを1つ渡しても作れます。`名前 は 値` の後の「で」は、次に `名前 は` が続くときだけ組の続きと読みます。
30. **組は変更できない値。** `p の 横` で取り出し、`横 は 10 の p` で横だけ変えた新しい組を作ります(p はそのまま)。中身が同じなら `が` で等しくなります。表示は `（横 は 3 で 縦 は 4 の 点）` で、そのまま書き戻せます。
31. **パターンマッチは「もし 値 が パターン ならば …」。** `もし 形 が` の後の深い行(句読点の書き方では「、」の区切り)に `パターン ならば 式` を並べ、上から順に最初に当てはまった場合を使います。最後に `そうでなければ …` を書くと、残りすべてに当てはまります。1つだけなら `もし 形 が 半径 の 円 ならば 半径 そうでなければ 0` と1行でも書けます。場合の本体の途中で式を区切りの先まで続けたいときや、場合の本体にさらに場合分けを書くときは括弧で囲みます。
   - パターンの `… の 形の名前` と `名前 は …` の中の名前だけが新しい変数になり、その場合の式の中で使えます。`空`、数、文字列、`真`/`偽`、中身のない形(`赤`)、すでにある変数、`a と b` のような値は「等しいか」を調べます(今までの `もし xs が 空 ならば …` は意味が変わりません)。
   - 入れ子は括弧で書きます: `（x と y の 点） と r の 円`。同じ名前を2回使うとエラーです。
   - `先頭 は x で 残り は 他` は、空でないリストを先頭と残りに分けます。名前つきのパターンでは `の 形の名前` を省けて、省くと「そのフィールドを持つ値なら何でも」になります。
   - 選択肢のある型の場合分けで形が足りず、`そうでなければ` もないときは、読み込み時に「「長方形」の場合がありません」のエラーになります。どれにも当てはまらない値が来ると実行時エラーです。
32. **性質(型クラス)は「… という 性質 とは」で定義する。** 深い行に、関数の宣言(本体なし: `a と b を 比較する`)と、既定の実装(`… とは …`)を並べます。句読点の書き方では `比較可能という性質とは、aとbを比較する。ただし、…とは、…。` のように「ただし」で付け足します(「ただし」の後には本体のない宣言も書けます)。
33. **性質の実装は「型 は 性質」。** `点 は 比較可能` の下の深い行(句読点の書き方では「ただし」)に、その型での関数を定義します。助詞は宣言と同じにします。宣言だけの関数を定義しないとエラーです。組み込みの型名は `数` `文字列` `真偽` `リスト` `関数` です。
34. **どの実装を使うかは「を」の値の型で決める。** 「を」を `a と b` で分解する関数なら最初の要素の型です(「を」がない関数は最初の引数)。実装していない型で呼ぶと「「文字列」は性質「比較可能」を持っていません」のエラーです。性質の関数は普通の関数と同じく `比較すること` で値にできます。性質の関数や中身のない形の名前は、ほかの定義で上書きできません。
35. **組み込みの性質「表示可能」。** 関数は `x を 文字列化する` の1つで、実装しなくてもすべての型が持っています(いつもの表示の文字列を返す)。実装すると、`表示する` やトップレベルの結果の表示、リストの中の表示がそれを使います。

### 動作(副作用)と手順

36. **副作用は「動作」という値。** `x を 表示する` や `入力する` は、その場では何もせず、表示や入力をする**動作**を返します。トップレベルの文の値が動作なら、その場で行います(その結果は表示しません)。動作でない値は今まで通り表示します。動作の型名は `動作` です。`（「a」 を 表示する） と 1` のように、作っただけで使わない動作は行われません。
37. **「…してから」はバインド。** `入力してから 数値にして 表示する` は、入力を行い、その結果を「数値にして 表示する」の「を」に渡します。「してから」の後ろは全部、前の結果を受け取る続きです。前の結果が動作でなければエラーです(純粋な値には「して」を使います)。続きが動作でない値を返したときは、それが全体の結果になります。
38. **「手順（文。文。…）」は do 記法。** 文を上から順に行い、最後の文が全体の動作(値)になります。空白の書き方では `挨拶する とは 手順` の後の深い行に文を並べます。手順の途中の文は動作でなければなりません(値を計算するだけの文はエラー)。「手順（」だけの行の後に句読点の書き方の行が続くときは、その行も句読点の書き方として読みます。手順の最後の文で自分を呼べば繰り返しになります(`n を 数え上げする とは 手順` の最後に `n + 1 を 数え上げする`)。1回ごとに表示や入力などの動作を行う繰り返しは、インタプリタでもコンパイルしたものでも、何回でも続けられます(サーバーの待ち受けの形)。
39. **「…した 結果」は、手順の中で動作を行った結果。** `名前 とは 入力した 結果` で結果に名前を付けます(普通の定義と同じ「とは」)。名詞なので、`入力した結果を数値にして、表示する。` のように手順の文の中のどこにでも書け、文の中で先に書いたものから行います。手順の外、関数の本体や「もし」の枝の中に書くとエラーです(そこを「手順（…）」で囲みます)。算術に使うときは `（入力した結果）+1` と括弧で囲みます。
40. **「の 結果」は写像。** `（入力する） の 結果 を 数値にする` は、入力の結果を数値にする動作です(「の それぞれ」がリストの要素ごとに呼ぶのと同じ形)。呼び出しの引数にだけ書けます。2つ以上の引数に書くと、前から順に行います。`結果` というフィールドを持つ組なら、今まで通りフィールドの取り出しです。
41. **「。それから、」は続けて行う。** `「やあ」を表示する。それから、「またね」を表示する。` は2つを順に行う1つの文になります。定義の後に書くと本体の続きになります(`ただし` と同じく直前の文に付け足す)。空白の書き方では `それから …` の行として書きます。
42. **性質「写像可能」と「連鎖可能」。** 組み込みの性質で、`写像可能` は `m を f で 写像する`、`連鎖可能` は `m を f で 連鎖する` と `x を 結果にする` を持ちます。リストと動作が実装しています(リストの連鎖は f の結果をつなげたリスト)。自分の型でも `『たぶん』 は 連鎖可能` として `連鎖する` を定義すれば、手順・「してから」・「の 結果」が使えます。`結果にする` は「を」の型で選べないので、いつも「何もしない動作」を作り、連鎖したときに相手の型に合わせます(その型で `x を 結果にする` を定義していればそれを使います)。

### 場合ごとの関数定義とパターンの条件

43. **パターンの条件は「かつ」。** 場合分けの `パターン かつ 条件 ならば 式` は、パターンに当てはまり、しかも条件が 真 のときだけその場合を使います。条件の中ではパターンで付けた名前が使えます(`半径 の 円 かつ 半径 > 10 ならば …`)。条件が 偽 なら次の場合に進みます。条件つきの場合は、形がそろっているかの確かめ(31番)の数に入れません。
44. **「かつ」「または」は真偽の計算。** 比較より弱く、「と」より強く結びつき、「かつ」のほうが「または」より強く結びつきます(`a または b かつ c` は `a または （b かつ c）`)。左で結果が決まれば右は計算しません。両側は 真 か 偽 でなければエラーです。パターンの直後の「かつ」は条件の始まりと読むので、`もし n が 0 かつ m > 1 ならば …` は「n が 0 で、しかも m > 1 なら」の意味になります(どちらに読んでも結果は同じです)。
45. **引数に値や形を書くと、場合ごとの関数定義になる。** `0 を 階乗する とは 1` のように、引数名の代わりにパターン(数、文字列、`空`、`真`/`偽`、中身のない形、`… の 形の名前`、`名前 は …`)を書けます。括弧の要る形は `（r の 円） を 面積にする` のように囲みます。パターンの中の名前だけが新しい変数で、名前だけの引数はどんな値にも当てはまります。`a と b を` は今までどおり2要素のリストを分けますが、場合ごとの定義の中では長さが違えば次の定義に進みます。
46. **同じ関数の定義は続けて書き、上から順に使う。** 続けて書いた同じ名前の関数定義は1つの関数にまとまり、呼び出すと、引数がすべて当てはまる最初の定義を使います。どの定義も同じ助詞を使います(違うとエラー)。すべての引数が名前だけの定義の後ろに、さらに定義を書くとエラーです(使われないため)。引数が1つで形の場合分けになっているなら、足りない形は読み込み時に「「面積にする」に「長方形」の場合の定義がありません」のエラーになり、どれにも当てはまらない値が来ると実行時エラーです。同じ関数を離れた場所でもう一度定義するとエラーです。局所定義(ただし)や性質の実装の中でも使えます。

### 述語

47. **「…である」で終わる名前は述語。** `n が 偶数である とは n % 2 が 0` のように、主語を「が」で受け、真か偽を返す関数です(ほかの助詞の引数も使えます: `a が b で 割切である`)。真偽以外を返すと実行時エラーです。名前の決まりは「する」の関数と同じで、「である」の前に漢字かカタカナが必要です。
48. **呼び出しは「…である」「…でない」、値は「…であること」。** `4 が 偶数である` は 真、`3 が 偶数でない` は否定です(「でない」は定義しなくても使えます。「…でない とは」と定義するとエラー)。`偶数であること` は「すること」と同じく述語そのもので、`リスト から 偶数であること で 選別する` のように渡せます。部分適用もできます。
49. **述語の前の「が」は主語。** 「が」の後ろを読んでいって、呼び出しの終わりが述語なら、その「が」は主語の助詞です。そうでなければ今までどおり「等しいか」です(`リスト が 空` は変わりません)。`もし n が 偶数である ならば …` もそのまま書けます。「…して」の結果は、述語では「を」でなく「が」に入ります(`5 を 三倍して 偶数である`)。
50. **述語どうしは「かつ」「または」でつなげる。** `n が 正である かつ n が 偶数でない` のように、呼び出しを含む条件も「かつ」「または」でつなげます(44番と同じ結びつきの強さ)。パターンの条件(43番)にも書けます。

### 型の検査

51. **実行の前に必ず型を調べる。** `python3 suru.py ファイル` は、まず型の間違いを探し、見つかれば何も実行せずにエラーを表示します。型は書かなくても推論します(Hindley–Milner)。`--検査` は調べるだけで実行せず、`--検査なし` は調べずに実行します(違う型を混ぜたリストなど、型の検査では通らないが動く書き方を試すとき)。対話モードは今までどおり型を調べません。
52. **型の名前。** `数` `文字列` `真偽`、`数 の リスト`、`文字列 の 動作`、組や選択肢のある型はその型名、関数は `（数 を 受け取って 数 を 返すこと）` と表示します。まだ決まっていない型は 甲・乙・丙 … です。
53. **リストの要素の型はそろえる。** `1 と 「a」` はエラーです。違う型の値をまとめるときは組か選択肢のある型を使います。
54. **「+」は同じ型どうし。** 数・文字列・リストを、同じ型どうしでだけ足せます。数を文字列につなぐときは `（x を 文字列化する）` を使います(実行のときは今までどおりつなげます)。`<` などの大小の比較は数どうし、`が`・`==` は同じ型どうしです。
55. **呼び出しは助詞ごとに調べる。** 受け取らない助詞、足りない引数、型の違う引数は、実行する前にエラーになります。関数の値(`三倍すること`)を渡すときは、助詞ではなく引数の順番で合わせます。`加算する` は「を」がリストなら全部を足し、「に」があれば2つを足すように、特別に調べます。
56. **定義は多相。** `x を 恒等にする とは x` は数にも文字列にも使えます。一番外と「ただし」の定義は、互いに呼び合うものをまとめて推論します。自分自身や互いを呼ぶところでも、引数の型を調べます。
57. **性質の関数は、実装の型で調べる(第2段階)。** `a と b を 比較する` のような性質の関数の呼び出しは、「を」の値の型(34番と同じ決め方)が分かったところで、その型の実装(なければ既定の実装)の型と合わせます。実装していない型で呼ぶと「文字列は性質「比較可能」を持っていません」のエラーになります。性質の関数を使う多相な関数(`a と b を 大きい方にする`)は「この性質を持つ型なら何でもよい」という条件つきの型になり、呼んだところで確かめます。`表示可能` の `文字列化する` の実装は文字列を返す必要があります。
58. **型の条件も呼んだところで確かめる。** `x の 長さ`(文字列かリスト)や `a + b`(数・文字列・リスト)のように型の種類にしばりのある多相な関数は、そのしばりを型に持たせて、呼んだところで確かめます(`「測る数にする」に渡した値: …`)。
59. **自分の型は型の引数をとる(第3段階)。** 書き方は今までのままで、フィールドごとに型を推論します。`（1 の 有）` は `数 の たぶん`、`（「a」 の 有）` は `文字列 の たぶん`(『』の型 `『たぶん』` の値) で、どちらも同じプログラムで使えます(フィールドが2つ以上なら `（数 と 文字列） の 点`)。ただし同じリストに入れるなら、中身の型もそろえます。
60. **自分自身を中に持つ型。** `木 とは 値 と 左 と 右 の 節 か 葉` の「左」「右」のように、その型自身(やそのリスト)を入れるフィールドは、型の引数にせず「その型」とします(`数 の 木`)。定義から決めるのではなく、推論の途中で型が無限に続くと分かったところで、そのフィールドをその型にして推論し直します。
61. **いつも同じ型で使うフィールドは、型名だけで表示する。** プログラムの中でいつも数として使う「半径」のように、使い方が1通りのフィールドしかない型は、エラーでは `（数 と 数 と 数） の 図形` ではなく `図形` と表示します。どんな型でもよい引数も省きます。
62. **動作の型(第3段階)。** `「?」 を 入力する` は `文字列 の 動作`、`x を 表示する` は動作、`動作のリスト を 実行する` は結果のリストの動作です。`… してから …`・手順の `… した 結果`・手順の途中の文は、前の値が動作(や連鎖可能な型)であることと、その結果の型を続きに渡して調べます(`入力してから 三倍する` は「「三倍する」の「を」には数が必要ですが、文字列が渡されています」)。手順の最後の値が動作でなければ、何もしない動作になります。
63. **`結果にする` は、連鎖する相手の型になる。** `x を 結果にする` は「x を結果にしたもの」という型で、動作・リスト・自分の連鎖可能な型のどれとも、結果の型が x の型と同じならそろいます(自分の型で `結果にする` を定義していれば、その型で調べます)。
64. **`の 結果`・`写像する`・`連鎖する` も型を調べる。** リストと動作のほか、`写像可能`・`連鎖可能` を実装した自分の型では、その実装(`連鎖する`・`写像する`)の型で調べます。どちらも持たない型に使うと「数は性質「写像可能」を持っていません」のようなエラーになります。動作を `+` などで直接計算すると、「…してから」か「の 結果」を使うようにエラーで知らせます。

### 丁寧語の文末

65. **「します」「しまして」は「する」「して」と同じ。** `5を三倍します。` は `5を三倍する。`、`5を三倍しまして、表示します。` は `5を三倍して、表示する。` と同じ意味です。「しましてから」は「してから」と同じです。どちらの書き方でも使えます(空白の書き方なら `5 を 三倍します`)。関数の名前は今までどおり「する」で終わる名前で、定義も `n を 三倍する とは …` のまま書けます(`n を 三倍します とは …` と書いてもかまいません)。
66. **文末の「です」は読み捨てる。** `p とは 3 と 4 の 点 です。`、`x とは 7です。`、`もしn>0ならば「正」です、そうでなければ「負」です。` のように、「。」「、」「）」「そうでなければ」の前か、空白の書き方の行の終わりに書いた「です」は飾りとして読み飛ばします。それ以外の場所(`3 です と 4`)に書くとエラーです。「です」「ます」はひらがななので、ひらがなを含む名前を『』で囲む決まり(23番)のおかげで名前とぶつかりません。

### 型の宣言(第4段階)

67. **型は宣言してもよい。** 定義の前(か後ろ)に、引数名の代わりに型名を書き、「は」の後に値の型を書きます: `数 を 階乗する は 数`、`税率 は 数`、`数 が 偶数である は 真偽`、`挨拶する は 数 の 動作`。句読点の書き方では `数を階乗するは、数。` です。宣言は型の検査だけで使い、実行には影響しません。書かなくてもかまいません。
68. **型の書き方。** `数` `文字列` `真偽`、`数 の リスト`、`文字列 の 動作`、関数は `（数 を 受け取って 数 を 返すこと）`(助詞が複数なら `（数 を 数 で 受け取って 数 を 返すこと）`)、自分の型は `点`(フィールドの型は推論に任せる)や `（数 と 数） の 点`、`数 の 『たぶん』` です(型の引数はフィールドの順。自分自身を入れるフィールドは数えません)。`点 は 比較可能` のように「は」の後が性質なら、今までどおり性質の実装です。
69. **宣言と定義が違えばエラー。** 宣言と定義で助詞が違う、値の型が違う(「「税率」は文字列と宣言されていますが、数になっています」)、宣言だけで定義がない、同じ名前を2回宣言する、のどれもエラーです。宣言した型は、定義の中の自分自身の呼び出しにも使います。
70. **甲・乙 は「どんな型でもよい」。** `甲 を 恒等にする は 甲` は、どの型にも使える関数の宣言です。定義が数でしか使えないなど、甲 が決まった型になったり、甲 と 乙 が同じ型になったりするとエラーです。宣言は一番外の定義にだけ書けます。

### ファイルの読み込み

71. **`「数学」 を 読み込む` で、同じフォルダの `数学.suru` を読み込む。** 一番外に書きます(句読点の書き方なら `「数学」を読み込む。`、丁寧語なら `読み込みます`)。フォルダは、実行しているファイルのフォルダから探します(`「部品/数学」` のように下のフォルダも書けます)。ファイルの名前は、変数の名前と同じく漢字・カタカナ・英字で書きます。同じファイルは何度読み込んでも1回だけ読みます。自分自身を読み込むことになる読み込みはエラーです。
72. **中の名前は「ファイル名内の名前」で使う。** 読み込んだファイルの一番外の定義は `数学内の円周率`、`3 を 数学内の二乗する`、`数学内の二乗すること` のように、ファイルの名前と「内の」を前に付けて使います(空白の書き方でも `数学内の円周率` か `数学内の 円周率`)。「数学」を読み込んでいなければ `数学内` はふつうの名前です。前に付けずに `円周率` と書いても読み込んだ定義にはならないので、自分のファイルで同じ名前を定義してもぶつかりません。読み込んだファイルがさらに読み込んだファイルの名前は使えません。使うなら、そのファイルも読み込みます。
73. **型・形・性質は「内の」なしで使える。** 読み込んだファイルで定義した型(`図形`)、形(`（2 の 円）`)、性質とその関数、性質の実装は、そのまま使えます。型と形の名前は、読み込んだファイルを含めてプログラム全体で1つの型にしか使えません。
74. **読み込むファイルには定義だけを書く。** 定義・型・性質・型の宣言・読み込み以外の文(`x を 表示する` など)があるとエラーです。読み込んだファイルの中の間違いは「「数学.suru」の2行目: …」のように、ファイルの名前と行を付けて、読み込んだ行で知らせます。型の検査も読み込んだファイルまで行います。

75. **`「数学」 を 読み込んで 使う` なら前置きなしでも使える。** 中の名前を `円周率`、`3 を 二乗する` のようにそのまま使えます(`数学内の円周率` も使えます)。句読点の書き方なら `「数学」を読み込んで使う。`、丁寧語なら `読み込んで使います`。自分で同じ名前を定義すると自分の定義が使われ、読み込んだファイルのものは `数学内の…` で使えます。「読み込んで 使う」にした2つのファイルに同じ名前があると、自分で定義していない限りエラーです(片方を「読み込む」にするか、前置きを付けて使います)。
76. **見つからないファイルは標準のフォルダから探す。** 実行しているファイルのフォルダになければ、`suru.py` の隣の `lib` フォルダから探します。標準ライブラリ `lib/標準.suru` はこうして読み込みます。

77. **`「標準」 を 読み込む` で標準ライブラリを使う。** `標準内の逆順にする` のように前置きを付けて使います。`「標準」 を 読み込んで 使う` なら前置きなしです。中身は `lib/標準.suru` に する で書いてあり(型の宣言つき)、文字列の操作のように する では書けないものだけが組み込みです。組み込みも、標準を読み込んだときだけ使えます。
78. **位置は1から数える。** `xs から 1 を 番目取得する` が先頭です。範囲の外はエラーです。

### コンパイラ

80. **`python3 suru.py --翻訳 prog.suru` で実行ファイルを作る。** `suru_compile.py` が する のプログラムを LLVM IR にし、clang で実行時ライブラリ(`runtime/suru_rt.c`)と一緒に1つの実行ファイル `prog` にします。`-o 名前` で出力の名前、`--ll` で LLVM IR(`prog.ll`)だけを出します(`python3 suru_compile.py --ll prog.suru`)。clang は `CC` で別のものにもできます。
81. **結果はインタプリタと同じ。** 型の検査をしてからコンパイルします(`--検査なし` で外せます)。読み込み・標準ライブラリ・性質・動作と手順・場合ごとの定義など、全部の書き方が使えます。実行時のエラーもインタプリタと同じ文で、終了コードは 1 です。テスト(`tests/test_compile.py`)は、例のプログラムなどをコンパイルして、インタプリタと出力が同じかを調べます。
82. **速い・深い再帰も動く。** 関数は機械語の関数になり、整数の計算はその場で行います。再帰は 1GB のスタックで動くので、インタプリタでは止まる深さ(10万段など)でも動きます。
83. **インタプリタとの違い。** 整数は ±4611686018427387903(2^62 − 1)までで、超えると「整数が大きすぎます」のエラーです(インタプリタはいくらでも大きくできます)。`大文字にする` / `小文字にする` が変えるのは英字(半角と全角)だけです。使い終わったメモリは GC(保守的なマーク&スイープ)が片付けます。スタックやレジスタにある「オブジェクトを指していそうな値」はすべて使っているとみなし、オブジェクトは動かしません(`runtime/suru_rt.c` の「メモリ」の節)。8MB 確保するごとか、前回残った量と同じだけ確保するごとに動きます。`SURU_GC_LOG=1` で GC のたびに残った量を表示し、`SURU_GC_MIN=KB` で動く間隔の下限を変えられます(`0` なら確保のたびに動く。テスト用)。対話モードはありません。

### 配布

84. **pip で入れられる。** `pip install .`(または GitHub の URL)で `suru` コマンドが入ります。中身は `suru.py`・`suru_check.py`・`suru_compile.py` の3つのモジュールと、`suru_data/` に入れた `lib/` と `runtime/` です。リポジトリのまま `python3 suru.py` で動かす使い方も変わりません(`data_path` が、隣の `lib/` か `suru_data/lib/` を探します)。版は `suru.py` の `__version__` に書きます。パッケージ作りは hatchling(`python -m build` で wheel と sdist)。

85. **ライセンスは2つに分ける。** インタプリタ・型検査・コンパイラ(`suru.py`・`suru_check.py`・`suru_compile.py`)は GPL-3.0-or-later(`LICENSE`)です。実行時ライブラリ(`runtime/`)と標準ライブラリ(`lib/`)は MIT(`runtime/LICENSE`・`lib/LICENSE`)です。この2つはコンパイルしたプログラムや する のプログラムに一緒に入るので、MIT にして、作ったプログラムに GPL が及ばないようにしています。

### Go 版のコンパイラ

86. **Go 版のコンパイラ `suruc`。** `compiler/`(字句解析・構文解析・型の検査・IR の生成)と `cmd/suruc/`(clang の呼び出し)を Go で書き、Python 版と同じ IR・同じエラーの文を出します。`tests/test_go_compiler.py` が、例と、テストに書いた全部のプログラム(エラーになるものも)で、Python 版と出力が同じかを調べます(go がなければ飛ばします)。Python 版を直したら、Go 版も同じに直します。
87. **型の検査は行数に比例する時間。** Python 版では、定義を1つ推論するたびに、それまでの全部の定義の型をなめていたので、定義の数の2乗の時間がかかっていました。Go 版は、環境の中の自由な型変数を覚えておいて使い回します(多相にした型変数が後から決まったときだけ作り直します)。8,000 行のプログラムで、検査は 10.2 秒 → 0.03 秒です。
88. **時間のほとんどは clang。** 8,000 行のプログラムで、IR を作るまでは Python 版 13.6 秒 → Go 版 0.4 秒、バイナリまでは 28 秒 → 18 秒(-O2)/ 2.4 秒(-O0)です。clang の時間を減らすには、IR を小さくするのが次の手です。

### 通信

89. **`「通信」 を 読み込む` で TCP の通信をする。** 組み込みは6つで、どれも動作を返します。待受口と接続は1からの番号で表します(インタプリタとコンパイルしたもので同じ番号)。

| 書き方 | 結果(動作の結果) |
|---|---|
| `8080 を 通信内の待受開始する` | 待受口の番号(0.0.0.0 のそのポートで待ち受ける) |
| `口 から 通信内の接続受付する` | 接続の番号(次の接続が来るまで待つ) |
| `接続 から 通信内の行受信する` | 1行の文字列(終わりの改行を含む。相手が閉じていれば「」) |
| `接続 から 100 を 通信内の受信する` | 100 バイトまでの文字列(UTF-8 として読む) |
| `文字列 を 接続 へ 通信内の送信する` | 送ったバイト数 |
| `番号 を 通信内の切断する` | 接続か待受口を閉じる(結果は番号) |

90. **通信の失敗は実行時エラー。** 相手が切れたときなどは「「送信する」で通信に失敗しました(Broken pipe)」のエラーです。開いていない番号はエラーです。コンパイルしたものは、接続を待つ前・受信する前にそれまでの表示を出します(ログが遅れて出ないように)。
91. **組み込みは lib/ のファイルごと。** `suru.py` の `LIB_PRIMITIVES`(Go 版は `libPrimitives`)で、どのファイルの中で見えるかを決めます。実行時ライブラリの中では、標準と通信の組み込みは同じ表です。

### HTTP

92. **`「HTTP」 を 読み込む` で HTTP サーバーを作る。** 要求を受け取って応答を返す関数を書き、`待受する` に渡します。中身は `lib/HTTP.suru` に する で書いてあり(通信の組み込みの上)、インタプリタでもコンパイルしたものでも動きます。

```
「HTTP」 を 読み込む

要求 を 案内する とは
  もし 要求 の 道 が
    「/」 ならば 「こんにちは」 を HTTP内の本文応答する
    そうでなければ 404 で 「見つかりません: 」 + 要求 の 道 を HTTP内の状態応答する

8080 を 案内すること で HTTP内の待受する
```

93. **要求と応答は組。** `要求` は 方法(「GET」など)・道(「/a?b=1」のまま)・見出し・本文、`応答` は 状態・見出し・本文 です。見出しは「名前 と 値」のリストのリストで、要求の見出しの名前は小文字にそろえます(`要求 から 「X-Name」 を HTTP内の見出し値にする` は大文字小文字を区別せずに探し、なければ「」)。
94. **応答を作る関数。** `本文 を 本文応答する`(200、text/plain)、`本文 を HTML応答する`(200、text/html)、`404 で 本文 を 状態応答する`、`応答 に 「X-A」 と 「1」 を 見出し追加する`。送るときに Content-Length と `Connection: close` を足します。`応答 を 応答文にする` は送る文字列です。
95. **動作を返す関数なら `動作待受する`。** 要求ごとに表示したり、ファイルを読んだりするときは、関数が応答の動作を返すようにして(`… を HTTP内の本文応答して 結果にする`)、`8080 を 記録すること で HTTP内の動作待受する` と書きます。
96. **1件ずつ順に答える。失敗しても止まらない。** 要求を読み、関数を呼び、応答を送って接続を閉じ、次の接続を待ちます。1件ごとに `試行する` で囲むので、関数が実行時エラーになったら 500 を返し、壊れた要求や途中で切れた相手はその接続だけ閉じます(エラーの文は標準エラーに出ます)。つないだまま何も送らない相手は5秒で見切ります。
97. **例は `examples/http.suru`。** `python3 suru.py examples/http.suru` で起動して、ブラウザで http://localhost:8080/ を開きます。要求ごとに「GET /hello?name=taro」のように表示します。
98. **速さとメモリ(手元で計測)。** この例で、コンパイルしたものは約 6,000 件/秒、インタプリタは 1000 件 1.1 秒(約 880 件/秒)です。メモリはどちらも増えません(コンパイルしたものは 3万件続けて約 13MB のまま、インタプリタは約 30MB のまま)。テストは、バイナリに1万件続けて聞いて全部 200 が返るかを調べます。

### 外部の関数(C・C++・Go を呼ぶ)

99. **`外部の「m」 を 読み込む` と `… とは 外部の「cos」` で C の関数を呼ぶ。** 型の宣言で C の型を決め、定義の本体を `外部の「C の名前」` にします。引数は定義に書いた順に C へ渡ります。libc の関数(`strlen` など)は読み込まなくても使えます。例は `examples/ffi.suru`。

```
外部の「m」 を 読み込む
小数 を 小数 で 累乗する は 小数
x を y で 累乗する とは 外部の「pow」
2 を 10 で 累乗する                    # 1024
```

100. **型の対応。** `数` は `int64_t`、`小数` は `double`、`整数` は `int`、`真偽` は `int`(0 か 1)、`文字列` は `const char *`(UTF-8)、`番地` は `void *`、`バイト列` は `const uint8_t *`(引数だけ)、`無` は `void`(値だけ)です。`小数` と `整数` は、する の中では `数` と同じ型です。`番地` は中を見ない値で、`番地(0x…)` と表示し、`=` で比べられます。リスト・組・関数は渡せません。戻り値の `int64_t` が ±2^62 を超えたら実行時エラーです(コンパイルしたものの整数の範囲)。C が NULL の文字列を返したら「」です。
101. **値が動作なら、行ったときに呼ぶ。** `数 を 加算記録する は 数 の 動作` と宣言すると、呼んでも動作を作るだけで、手順やトップレベルで行ったときに C の関数を呼びます。動作でない型なら、その場で呼ぶ純粋な関数として扱います(本当に副作用がないかは、宣言した人が決めます)。
102. **ライブラリの名前。** `「m」` のような短い名前は OS の探し方で探します(コンパイルしたものは `-lm` でリンク)。`/` を含むか `.so`・`.dylib` で終わる名前は、そのファイルからの相対パスです(コンパイルしたものはそのファイルをリンクし、実行時に同じ場所から読みます)。
103. **自分で書いた C・C++・Go を呼ぶ。** C は `cc -shared -fPIC -o libあれ.so あれ.c`、C++ は出す関数を `extern "C"` にして同じように、Go は `//export 名前` を付けて `go build -buildmode=c-shared -o libあれ.so` で作り、`外部の「./libあれ.so」 を 読み込む` で使います。
104. **作り。** インタプリタは Python の `ctypes`、コンパイラ(Python 版と Go 版)は IR に `declare` を書き、値の変換は実行時ライブラリの `rt_ffi_*` で行います。C に渡した文字列は呼んでいる間だけ使えます(C 側で持ち続けるものは `番地` で扱います)。C から する の関数を呼び戻すことはまだできません。
105. **バイト列。** 変更できないバイトの並びで、`バイト列（e3 81 82）` と表示し、`=` で中身を比べます。標準の組み込みで作ったり戻したりします: `s を バイト列にする`(UTF-8)、`（65 と 66） を バイト列組立する`(0〜255 の数のリストから)、`b を 数列にする`、`b を 文字列にする`(UTF-8 でなければ実行時エラー)、`b を バイト長にする`。外部の関数の引数の `バイト列` は `const uint8_t *` です(長さは別の引数で渡します。C 側で書き換えません)。
106. **C のメモリとのやりとり。** `n を 番地にする`・`p を 番地数値にする` で数と番地を行き来し(`0 を 番地にする` が NULL)、`p から n を バイト列取得する` で C のメモリから n バイトを写し取り、`b を p へ 書込する` で書き込みます(どちらも動作)。メモリは `malloc`・`free` を外部の関数として宣言して確保します。値のない C の関数(`void`)は、値の型を `無` と宣言します(する では 0 になります)。
107. **失敗の扱い。** `エラー番号取得する` は、直前に呼んだ外部の関数が残した errno を結果にする動作です(呼ぶ前に 0 にします)。`文 を 失敗する` はその文の実行時エラーになる動作で、`試行する` で受け止められます。標準の `m を 「開くの」 で 失敗確認する` は、C の関数が負の数を返したら「開くのに失敗しました(No such file or directory)」の実行時エラーにします(`e を エラー文にする` は strerror)。

### ファイルと環境

108. **`「ファイル」 を 読み込む` でファイルを読み書きする。** 中身は `lib/ファイル.suru` に する で書いてあり、C の stdio(`fopen`・`fread`・`fwrite` など)を外部の関数として呼びます。どれも動作です。

| 書き方 | 結果(動作の結果) |
|---|---|
| `道 を ファイル内の読込する` | ファイル全体の文字列(UTF-8) |
| `道 を ファイル内のバイト列読込する` | ファイル全体のバイト列 |
| `道 を ファイル内の行分割読込する` | 行の文字列のリスト(終わりの改行は含めない) |
| `文字列 を 道 へ ファイル内の書出する` | 書いたバイト数(ファイルは作り直す) |
| `文字列 を 道 へ ファイル内の追記する` | 書いたバイト数(終わりに足す) |
| `バイト列 を 道 へ ファイル内のバイト列書出する` | 書いたバイト数 |
| `道 を ファイル内の存在確認する` | ファイルかフォルダがあれば 真 |
| `道 を ファイル内の削除する`、`道 を ファイル内のフォルダ作成する` | 0 |

109. **失敗は実行時エラー。** 「ファイル『a.txt』を開くのに失敗しました(No such file or directory)」のような文で、`試行する` で受け止められます。道は今のフォルダからの相対パスです(プログラムのファイルからではありません)。
110. **`「環境」 を 読み込む` でプログラムの環境を使う。** `環境内の引数取得する`(`suru 例.suru a b` や `./例 a b` の a と b のリスト)、`「HOME」 を 環境内の環境変数取得する`(なければ「」)、`3 を 環境内の終了する`(表示を出し切ってから終える)、`「…」 を 環境内のエラー出力する`(標準エラーに1行)、`環境内の今のフォルダ取得する`。引数と終了だけは組み込み(標準の `引数取得する`・`終了する`)で、ほかは外部の関数です。

### 文字の分類と字句解析(する で書いたもの)

111. **`「文字」 を 読み込む` で1文字の種類を調べる。** `c が 文字内の平仮名である`・`片仮名である`・`漢字である`・`英字である`(半角と全角)・`数字である`(半角と全角)・`空白である`、`c を 文字内の半角にする`(全角の英数字・記号と全角スペースを半角に)、`s を 文字内の半角変換する`。中身は `lib/文字.suru` に文字の番号の範囲で書いてあります。
112. **`「字句」 を 読み込む` で する のプログラムを字句解析する。** `行のリスト を 字句内の字句解析する` は、`suru.py` と同じ規則(空白の書き方・句読点の書き方・字下げ・「です」)で、論理行(`段`・`字句列`・`番号`・`閉`)のリストを返します。字句は `種類`(数・文字列・演算子・開き・閉じ・名前・予約語・助詞・呼出・句点・区切り)・`値`・`行`・`桁`・`形`・`囲`・`否定` を持つ組です。`suru.py` ならエラーになるところは種類が「誤り」の字句になり、その行(文)の残りは読みません。点検(linter)を する で書くための土台で、`tests/test_lexer.py` が例とライブラリの全ファイルで `suru.py` と同じ字句になることを確かめています。
